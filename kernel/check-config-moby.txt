How it was run: docker run --rm -v ./checks:/c -w /c debian:trixie sh /c/check-config-moby.sh /c/config-7.2.6

Caveats, because this is an offline check of a config file and not of a running system:

  * The "cgroup hierarchy", "Controllers", "sysctl" and "/dev/zfs" lines describe the
    machine the script ran on (a container on the WSL2 host), not the kernel being
    checked. Ignore them here; they will be re-checked when the guest boots.
  * The script takes its version gates from `uname -r`, which reported the WSL2 host
    kernel 6.6.x rather than 7.2.6. Every gate in the script is for 5.x and older, so
    both versions take the same branches, and no check was skipped or added because
    of this.
  * BTRFS shows "enabled (as module)". It comes from the riscv defconfig, is not in
    our fragment, and will not load, since the initrd has no modules. Overlayfs, the
    storage driver we actually use, is built in.

Missing items and whether they matter here:

  * CONFIG_IP_SCTP: optional. Kubernetes supports SCTP service ports, but nothing in
    this single-node, no-network test uses SCTP. Left out deliberately.
  * CONFIG_CRYPTO_GHASH: the symbol no longer exists in 7.x. GHASH moved into
    CONFIG_CRYPTO_LIB_GF128HASH (lib/crypto/Kconfig), which CONFIG_CRYPTO_GCM selects,
    and it is =y in the final config. The script greps for the old name, so this line
    is cosmetic.
